# 日记模板 · Daily Note Template

一个 Obsidian 插件：**每次新建日记时自动套用模板**，而且模板里的两个列表会跟着「今天」的日记自己变化：

- **待办（To-do list）**：完整镜像今天的清单；第二天生成新日记时，所有勾选**自动还原成未勾选**。
- **紧急任务（Urgent mission）**：今天新加进来的会进入模板；今天打勾完成的**从模板里消失**（但当天日记里那条勾选记录不会被改动）。
- **每天自动开工**：哪天没开 Obsidian，下次启动时会把缺的日子按顺序补上，日记序列不会断；默认还会在当天第一次启动时自动打开今天的日记。
- **年 / 月节点**：每月自动生成月节点、每年自动生成年节点；月节点挂上年节点，日记末尾挂上所属月份，月节点里维护当月日记清单，年节点里维护月份清单。

---

## 它是怎么工作的

模板是一个骨架 + 两个占位符：

```markdown
# To-do list
{{todo_list}}

## Urgent mission
{{mission_list}}

# Exercise

{{cursor}}
```

| 占位符 | 生成新日记时填什么 |
| --- | --- |
| `{{todo_list}}` | 「今天」日记里 `# To-do list` 区块的全部条目，**复选框一律还原成 `- [ ]`** |
| `{{mission_list}}` | 「今天」日记里 `## Urgent mission` 区块中**没有打勾**的条目；打勾的直接不带 |

触发时机：

1. **实时**：只要改动今天的日记，停手约 0.7 秒，模板里的两个列表就会跟着更新（设置页能看到同步状态和预览）。
2. **打开今天日记**时也会对齐一次。
3. **生成新日记**时，插件会重新读「目标日期之前最近的一篇日记」，所以即使 Obsidian 没开着、隔了几天，行为也一致。
4. 想手动刷新，用命令 **「日记模板：从今天的日记同步模板列表」**。

结果就是：今天的待办清单 = 明天的待办清单（勾去掉）；今天的紧急任务里没做完的，明天继续在；做完的，明天自然消失。

## 每天自动补建 / 自动打开

**核心保证：日记序列不会因为某天没开 Obsidian 就断开。** 每次启动都会检查「上一篇日记」和今天之间缺了哪些日子，按顺序用模板补齐。

| 时机 | 行为 |
| --- | --- |
| Obsidian 启动 | 从「最近一篇日记」的第二天一直补到今天，中间缺几天补几天；补出来的内容和正常生成一样（待办镜像前一天、勾选还原、完成的紧急任务不带） |
| 一直开着跨过零点 / 休眠唤醒 | 每分钟检查一次日期，发现日期变了就把缺的日子补上，不抢焦点 |
| 今天已经被建过 | 不重复创建；你主动删掉今天的日记后，当天不会每分钟反复重建 |
| 仓库里还没有任何日记 | 只建今天，不往回追溯 |
| 缺的日子多于上限 | 只补最近 N 天（默认 31 天，可改） |

**历史空档需要手动补。** 自动补建只向前看：如果你在 11-20 之后直接写了 11-23，11-21、11-22 不会被自动翻出来（否则你删掉的旧日记会被反复重建）。想补这些日子，运行命令 **「日记模板：补齐最近缺失的日记」**，或点设置页里的 **「立即补齐最近 N 天」**，它会扫描最近 N 天把所有空档填上。

设置里可以控制：

- **自动补建缺失的日记**（默认开）：关掉后只有你主动打开日记才会创建。
- **最多向前补几天**（默认 31）：往回找多少天，避免第一次启用就把很久以前的日子全建出来。
- **自动打开今天的日记**（默认「每天首次启动打开」）：
  - `不自动打开`：只创建，不动你正在看的笔记；
  - `仅新建时打开`：只有今天刚被补建出来那一次会打开；
  - `每天首次启动打开`：每天第一次开 Obsidian 时切到当天的日记。

> 补建发生在后台，只有"自动打开"这一项会切换你正在看的笔记；跨天补建永不抢焦点。

## 年 / 月节点

每次创建日记时，插件会顺手把这一天所属的年节点、月节点建好并接上链接：

```markdown
# 2026-11-23.md（日记）
...
所属月份：[[2026-11]]
```

```markdown
# 2026-11.md（月节点）
# 2026年11月

所属年份：[[2026]]

## 日记

- [[2026-11-19]]
- [[2026-11-20]]
- [[2026-11-21]]
- [[2026-11-22]]
- [[2026-11-23]]
```

```markdown
# 2026.md（年节点）
# 2026年

## 月份

- [[2026-11]]
```

规则：

- 当月第一篇日记创建时生成月节点，当年第一个月节点创建时生成年节点（每月的第一天、每年第一天自然会走到）。
- 月节点创建时自动写上 `所属年份：[[2026]]`；年节点的「## 月份」清单会自动补上这个月。
- 月节点的「## 日记」清单会扫描当月**所有已存在的日记**，所以补建/新增日记都会自动出现（不重复、按创建顺序排列）。
- 日记里的 `所属月份：[[2026-11]]` 默认加在文末；想换位置就在模板里写 `{{month_link}}`。
- 节点位置默认和日记同目录，也可以在设置里指定「节点存放文件夹」；文件名格式 YYYY-MM / YYYY 可改。
- 旧日记归档在别的文件夹（比如 `生活/日记`）时，把目录填进设置的「额外日记文件夹」，它们同样会被补链接、计入月节点清单。

> 这两个清单是"只增不删"的：删掉某篇日记不会被自动从月节点里移除（避免误删清单内容），需要时手动删那一行。

## 安装

### 方式 A：手动安装

把 `daily-note-template` 文件夹放进仓库的 `.obsidian/plugins/` 目录，重启或重载 Obsidian（`Ctrl+R`），再到「设置 → 第三方插件」启用。

```
你的仓库/
└── .obsidian/
    └── plugins/
        └── daily-note-template/
            ├── main.js
            ├── manifest.json
            └── styles.css
```

### 方式 B：从源码构建

```bash
pnpm install
pnpm build   # tsc 类型检查 + esbuild 打包
pnpm test    # 全部测试
```

## 使用

1. 启用后打开 **设置 → 日记模板**。
2. 把模板写成你每天要的结构，两个 `{{...}}` 占位符按需摆放（也可以换标题名，见下）。
3. 点左侧日历图标或命令面板 **「日记模板：打开今日日记」**。

默认模板：

```markdown
# To-do list
{{todo_list}}

## Urgent mission
{{mission_list}}

# Exercise

{{cursor}}
```

## 设置项

| 设置 | 说明 |
| --- | --- |
| 模板来源 | 「内置文本」直接在设置页编辑；「笔记文件」用一个 Markdown 笔记当模板 |
| 模板文件路径 | 「笔记文件」模式下的模板位置，文件不存在时自动创建 |
| 待办区块标题 | 日记里哪个标题下是待办，默认 `To-do list`（忽略大小写） |
| 紧急任务区块标题 | 日记里哪个标题下是紧急任务，默认 `Urgent mission` |
| 待办列表跟随今天的日记 | 关掉后改用「初始待办」 |
| 紧急任务跟随今天的日记 | 关掉后模板里紧急任务永远为空 |
| 初始待办 | 只有「还没有可同步的日记」时才用的种子清单 |
| 模板里没写占位符时也插入列表 | 兜底：列表会追加到同名标题下 |
| 跟随 Obsidian「日记」核心插件 | 直接使用官方插件的文件夹与文件名格式 |
| 日记文件夹 / 文件名格式 | 自定义位置，留空 = 仓库根目录 |
| 新建 / 打开空白日记时自动套用 | 两个自动写入时机 |
| 自动补建缺失的日记 | 启动时与跨天时把缺的日子全部补上 |
| 最多向前补几天 | 补建缺失日子的回溯上限（默认 31） |
| 自动打开今天的日记 | 不打开 / 仅新建时 / 每天首次启动 |
| 启用年 / 月节点 | 是否自动生成年、月节点并建立链接 |
| 月节点 / 年节点文件名格式 | 默认 `YYYY-MM` / `YYYY` |
| 节点存放文件夹 | 留空 = 与日记同目录 |
| 额外日记文件夹 | 旧日记归档目录（如 `生活/日记`），也纳入年/月节点索引，不会在里面新建日记 |

> 补建会从「上一篇日记」的第二天一路补到今天，中间缺几天就补几天（受「最多向前补几天」限制）。

> 自动套用只对**日记文件夹里、文件名符合日期格式**的笔记生效，且只写**空白**笔记。

## 可用变量

| 变量 | 含义 |
| --- | --- |
| `{{todo_list}}` | 待办列表（跟随今天，勾选还原） |
| `{{mission_list}}` | 紧急任务（跟随今天，已完成的剔除） |
| `{{date}}` / `{{date:YYYY年M月D日}}` | 日期 |
| `{{time}}` / `{{time:HH:mm:ss}}` | 时间 |
| `{{yesterday}}` / `{{tomorrow}}` | 昨天 / 明天（可用 `:格式`） |
| `{{weekday}}` | 星期几 |
| `{{title}}` / `{{filename}}` | 笔记标题（不含 `.md`） |
| `{{folder}}` | 笔记所在文件夹 |
| `{{cursor}}` | 打开日记后光标位置（不会留在正文里） |

## 命令

| 命令 | 作用 |
| --- | --- |
| 打开今日日记 | 不存在则按模板创建 |
| 打开指定日期的日记 | 补写/预写其他日期（会用那天之前最近的一篇日记做列表来源） |
| 从今天的日记同步模板列表 | 手动刷新模板里的两个列表 |
| 补齐最近缺失的日记 | 扫描最近 N 天，把历史空档一次补上 |
| 生成 / 更新年、月节点 | 立即建好今年、本月节点并补全清单 |
| 给已有日记补上月份链接 | 给功能上线前建的旧日记补上 `所属月份` 链接，并建好对应节点 |
| 把日记模板插入当前笔记 | 在当前光标处插入渲染好的模板 |
| 用模板重建当前笔记（覆盖正文） | 二次确认后整篇替换 |
| 编辑日记模板 | 打开模板文件（内置模式则打开设置页） |
| 预览模板渲染结果 | 先看渲染效果 |

## 常见问题

**昨天打勾的任务，今天为什么又出现了？**

这是设计如此：待办是「每日固定清单」，勾选只影响当天，第二天会还原成未勾选。

**一次性的任务怎么处理？**

放进 **Urgent mission**。它只有在没完成时才会带到下一天，打勾完成后第二天就不再出现，当天的记录仍然保留。

**模板里的列表会不会把我日记里已有的内容改掉？**

不会。插件只读取日记，从不修改已有的日记；它只写「新建出来的空白日记」。

**改了日记里的清单，模板多久生效？**

停手约 0.7 秒就会同步，设置页「列表同步」里能看到当前来源和最终会带走的条目。

**为什么一打开 Obsidian 就跳到了今天的日记？**

这是「自动打开今天的日记 → 每天首次启动打开」的默认行为。想要安静一点，把它改成「仅新建时打开」或「不自动打开」。

**跨天时会不会突然跳走？**

不会。跨天只静默创建新一天的日记，不切换你正在看的笔记。

**换了标题名（比如把 `To-do list` 改成 `待办`）怎么办？**

到设置里把「待办区块标题」一起改掉，模板里的占位符不用动。
